# 카드사 특가와 결제 행사 수집 계약

카드사 이벤트 등록 URL만으로는 쇼핑몰 상품 수집을 대체할 수 없다. 2026-10-17 Lifehack 보강에서는 상품 목록과 결제 프로모션을 분리하고, 실제 공개 화면의 요청 및 순회 계약을 HTTP 클라이언트로 옮겼다. 구현은 **Lifehack 앱의 `src/lib/hub/card-deals/providers`**에 있으며 이 Playbook에 새로운 실행 CLI를 추가한 것은 아니다.

## 페이지 누락을 막는 검증

1. 브라우저의 실제 다음 페이지 요청과 응답을 연결한다. 인근 bundle 문자열이나 다른 API의 페이지 이름을 빌리지 않는다.
2. 첫 페이지에 20개를 요청했어도 87행이 왔다면 임의로 20개로 자르지 않는다. BC의 `pgeCnt=20/allCnt=0`은 관측 응답 87행과 함께 존재했으며 실제 종결 신호는 `nextPageNo=0`이었다.
3. 요청 페이지와 응답 페이지, 고유 ID 진행, 반복 페이지, 총건수 변경, 명시적 종결을 확인한다. 페이지·행·본문 크기·시간에는 상한을 둔다. 상한 도달은 완료가 아니라 부분 범위다.
4. HTTP 200 오류 안내/설치 안내/로그인 페이지를 빈 목록 성공으로 파싱하지 않는다. 401/403/429는 해당 소스에서 중단한다.
5. 배치 저장은 source별 dedupe slot·lease·fence 및 원자적 receipt를 사용한다. 불확실한 완료 응답은 읽어서 대사하며 동일 slot을 재수집하지 않는다.

## 가격과 기간의 의미

삼성·신한 상품은 공개 일반가만 기본 가격으로 저장한다. 쿠폰/청구할인/포인트/회원가와 배송비 미확인은 각각 별도 사실로 보존한다. 나머지는 결제 행사이며 제목의 금액을 상품가격으로 추출하지 않는다.

BC `evntBltnStrtDtm/evntBltnEndDtm`은 **게재기간**이다. 상세의 `evntStrtDtm/evntEndDtm`과 다른 필드이므로 목록의 게재일을 행사 자격기간으로 바꾸지 않는다. 날짜만 노출된 다른 행사도 한국 날짜 기준과 정확한 시각 미확인을 함께 남긴다. 특정 카드사 쇼핑몰이라는 사실만으로 해당 카드 보유를 필수 조건으로 단정하지 않는다.

## 남은 경계

- KB Pay 앱 진입 링크와 실제 상품 문서는 다르다. 확인한 공개 상품 경로는 404였고, KB 공식 행사 수집은 해당 상품 문제 해결이 아니다.
- 현대 M몰 공개 PC 페이지는 PC 서비스 종료와 모바일/앱 안내였다. 공개 상품 목록 계약은 확보하지 못했다.
- NH는 필수 보안프로그램 설치 안내로 이동했다. 설치·로그인·UA 조작 없이 공개 목록 계약 확인 단계에서 멈췄다.
- 선택 표면의 종결은 전체 카드사 상품/회원 전용 특가의 종결이 아니다. 미구현 소스를 0건 성공 수집기로 등록하지 않는다.

원시 브라우저/계정 자료를 배포하지 않는다. 계약·테스트·정제된 결과 수·현재 미해결 표면만 공유한다.
