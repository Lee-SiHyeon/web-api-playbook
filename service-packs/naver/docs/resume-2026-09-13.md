# 재귀 탐색 재개 기록 — 2026-09-13

이 문서는 시간순 기록입니다. 앞부분의 실패·미검증 상태는 해당 시점의 결과이며, 최신 상태는 마지막 후속 기록과 `discovery/session-status.json`을 확인하세요.

## 실제 경계

`cua.getState`가 두 차례 `Unable to load browser request-header policy`로 실패했다. 브라우저 목록·탭·현재 네이버 인증 상태를 확인하지 못했다. 별도로 기존 Chrome의 DevTools 연결도 시간 초과였으며, 이 런타임에는 `NAVER_COOKIE`가 없었다. 따라서 이 기록은 **네이버가 접근을 거부했다거나 쿠키가 만료됐다는 증거가 아니다**. 최초 실패 경계는 로컬 브라우저 연결 정책 로딩이다. 다른 경로로 이 실패를 우회해 UI를 조작하지 않았다.

이번 실행의 새 화면 탐색·XHR 캡처·현재 인증으로 독립 HTTP 재현은 각각 0건이다. 전체 재귀 탐색은 미완료다. 저장된 대기열은 실행 중인 백그라운드 작업이 아니다.

## 완료한 로컬 변경

- 관측된 통계 GET 22개를 `scripts/client.mjs`의 명명된 읽기 어댑터로 구현했다. 경로와 쿼리 필드 이름은 기존 API 카탈로그에서 가져왔다. 시간 차원, 날짜, 제외 조건, 시간대, 캐시 구분값의 실제 값은 추정하지 않았다.
- URL 범위·중복/미관측 쿼리 필드를 검증하고, HTTP 상태·JSON MIME·숫자형 application status 200·통계 배열을 검사한다.
- 로그인 HTML, 리다이렉트, 403, 잘못된 스키마를 실패로 구분한다. 읽기 재시도는 기본 1회이며 429/502/503/504만 대상으로 한다. 5초보다 긴 Retry-After는 기다림을 줄여 재시도하지 않고 보류한다. 요청별 기본 제한은 20초·5 MiB다.
- 인증은 독립 실행 프로세스의 `NAVER_COOKIE`에서만 받으며, 정상 실행 코드는 브라우저를 import하거나 쿠키 파일을 찾지 않는다. `--data`를 명시한 경우에만 실제 응답 데이터를 출력한다.
- 원본 `recursive-map.json` 148개 노드와 모든 부모 관계를 보존해 `frontier.json`으로 정규화했다. 동일 쿼리 중복만 합치고 의미가 다른 선택자, 관리자 래퍼와 iframe은 임의로 합치지 않았다.
- 과거 iframe 관측에서 발견했지만 별도 노드가 없던 경로를 추가했다. JavaScript 링크 문자열은 실행하거나 잘못된 인코딩을 추측해 고치지 않고 후보로 보관했다. 일부 과거 inspected JavaScript 링크도 새 HTTP 방문 완료로 간주하지 않는다.
- `coverage.json`에 현재 범위, 구현과 실검증 상태, 공통 실패 경계, 다음 작업을 저장했다. 블로그 관리 하위 범위를 유지하며 다른 네이버 서비스로 확장하지 않는다.

정규화된 노드 수는 원본 메뉴 수·실제 기능 수와 다르다. 새 기능을 탐색해서 수가 늘어난 것이 아니라, 기존 iframe 증거와 아직 HTTP 경로로 확인하지 못한 컨트롤을 명시한 결과다.

## 연결 복구 후 실행

1. 기존 사용자 세션으로 `https://admin.blog.naver.com/4053103`의 계정·관리 권한을 확인한다. 현재 연결 정책 오류가 없어지고 수집기가 허용된 Network 이벤트를 실제 관측했을 때만 공통 실패 경계를 해제한다.
2. `frontier.json`의 BFS 대기열을 재개한다. `tools/discovery/frontier.mjs`는 큐/관측 병합 기능이며, 브라우저 수집기 자체는 아니다. CLI는 다음 작업을 출력할 뿐 자동 브라우징을 수행하지 않는다.
3. 페이지에서 실제 관측한 링크·iframe과 네트워크 요청을 연결한다. DOM 관측만으로 XHR 캡처 상태를 올리지 않는다. 새로운 링크의 동작 의미를 검토하기 전에는 candidate로 보존하며, 쓰기 동작은 실행하지 않는다.
4. 알려진 JSON 통계 요청은 정확한 현재 쿼리값으로 독립 `scripts/cli.mjs`에 재현하고, 성공한 호출별 증거를 남긴다. 하나의 경로 성공을 다른 필터·페이지의 성공으로 확대하지 않는다.
5. HTML/form 기반 관리 화면은 HTML 탐색으로 구분하고, JSON 계약이 확인되지 않았다면 XHR API로 보고하지 않는다. 로그인·캡차·권한 문제나 공통 실패가 발생하면 형제 경로를 보존한다.
6. 모든 요청된 분기와 관측한 페이지 구간을 처리했는지 범위별로 보고한다. 테스트 통과·많은 계약·메뉴 수로 전체 완료를 주장하지 않는다.

## 후속 재로그인

사용자가 재로그인과 세션 전달을 요청한 후 브라우저 연결은 정상화됐다. Chrome의 4053103 저장 계정으로 정상 로그인 버튼을 눌렀고 `https://admin.blog.naver.com/4053103` 관리자 화면의 계정과 관리 내비게이션을 확인했다. 비밀번호 표시 기능은 사용하지 않았고 자격증명을 출력하거나 파일에 저장하지 않았다.

## 후속 세션 전달·직접 호출·HTTP 전환

사용자가 Chrome의 디버깅 서버가 127.0.0.1:9222에서 실행 중임을 직접 확인했다. 허용된 연결에서 네이버 세션을 메모리로 읽어 별도 Node CLI 실행에 전달했고, 통계 GET 22개가 HTTP 200·application status 200·통계 배열 검증을 통과했다. 호출별 메타데이터는 `evidence/live-replays-2026-09-13.json`에 있으며 쿠키·비밀번호·응답 원문은 저장하지 않았다.

사용자가 컴퓨터 조작 없는 탐색을 요청한 뒤 화면 이동을 중단했다. HTML·iframe·JavaScript의 관측 경로를 HTTP로 따라가는 실행기를 준비했다. 이전 CLI 프로세스가 종료된 상태에서 새 실행기로 세션을 다시 전달하려 했으나 Chrome 연결 승인 요청이 300초 후 시간 초과됐다. 모든 작업 실행기를 중지하고 세션 메모리를 비웠다. 새 실행기의 인증된 HTML 재귀 탐색은 아직 수행하지 못했으며 전체 재귀 탐색은 미완료다.
