## 22:02 KST 헤드리스 재실행 검증

- 실제 런타임은 `Chrome/153.0.8010.12`였다. CDP 명령행 검사에서 headless,
  확장 비활성화, 자동화 표시를 확인했다. 정상 Playwright 실행과 네이버
  SDK를 사용하며 환경 위장, 토큰 변환 재구현, CAPTCHA 풀이를 추가하지 않았다.
- 현재 Chrome의 출처 한정 로그인 쿠키 두 개를 처음 한 번 메모리로
  전달했다. 이후 두 번의 발급은 별도 임시 headless context에서 수행했다.
  각 context는 같은 초기 세션을 받았으며, 비밀번호 로그인이나 로그인
  쿠키 자체의 갱신을 시험한 것은 아니다. 저장된 프로필·쿠키 파일은 없다.
- 두 실행 모두 SDK JS/WASM과 `POST /v2/tokens`가 HTTP 200을 반환했다.
  발급 응답은 `{ tokenId: string }`이었다. 실제 발행 폼의 SDK 토큰 두 개는
  서로 달랐고 실패 sentinel이 아니었다. 토큰 원문은 기록하지 않았다.
- 브라우저의 `/RabbitWrite.naver`는 각각 전송 전에 취소했다. 모든 블로그
  POST를 차단하여 자동저장도 전송하지 않는다. 그 뒤 브라우저를 완전히
  종료하고 두 번째 폼을 별도 Node 프로세스의 stdin으로 즉시 전달했다.
- HTTP 실행기 수신 시 관측 후 621ms였다. 이 값과 60초 전달 제한은
  네이버 토큰 TTL을 의미하지 않는다. 비공개 글 `224418033317`을 생성했고,
  제목은 `헤드리스 HTTP 신규 발행 검증 20260920`이다. 실제 HTTP 쓰기는 한 번이었다.
- 초기 실행 실패 두 건은 HTTP 실행기에 도달하지 않았다.
  구체적으로 확인된 실패는 늦게 표시되는 최초 도움말이 발행 버튼을 가린
  것이었다. 도움말 초기화를 기다리고 발행 패널을 열기 전에 재확인하도록 수정했다.

[headless-create-probe-cli.mjs](../apps/naver-blog-api/tools/discovery/headless-create-probe-cli.mjs)는
고정된 비공개 기술 문구만 사용한다. 정상 HTTP 발행기는 이 도구를 불러오지
않으며, 상업용 신규 발행은 계속 차단한다. 검증의 목적은 헤드리스 실행과
재발급·HTTP 전달이며 상업용 품질 게이트를 우회하지 않는다.

전체 테스트 **251개 통과**(공통 5, 제휴 28, 네이버 218). 추가된 8개 검사는
다른 계정·중복 자격·원고 변경·공개 범위 변경·미종료 브라우저·같은 토큰·

[헤드리스 검증 기록](../apps/naver-blog-api/references/ncaptcha-headless-verification-2026-09-20.json)에
실제 실행 결과와 영수증 해시를 남겼다.

**창·확장 없는 실행은 검증됐지만 브라우저 엔진 없는 API-only는 아니다.**
초기 세션 확보, 로그인 세션 만료 후 재인증, 장시간 무인 갱신, 서버의
토큰 만료·재사용 규칙, 다른 호스트·계정 및 상업용 발행은 검증 범위 밖이다.

## 21:12 KST 후속 검증

- 발급 응답 본문을 화면 전환 전에 메모리에서 확보했다. 구조는
  `{ tokenId: string }`이며 이번 응답 값은 88자, 실제 SDK가 발행 요청에
  넣은 값은 44자였다. 두 값은 달랐다. 응답의 `tokenId`를 그대로 발행
  토큰으로 사용하거나 길이를 고정 계약으로 간주할 근거는 없다.
- SDK가 만든 발행 요청을 `Request` 단계에서 잡아 `net::ERR_ABORTED`로
  취소한 뒤, 그 요청의 토큰과 문서만 자식 프로세스의 stdin으로 전달했다.
  로그인 쿠키는 허용된 자식 환경 변수로 전달했다. HTTP 쓰기의 자격과
  데이터는 파일이나 명령행에 저장하지 않았다.
- 첫 시도는 도구 정리 중 로컬 전달 제한 60초를 넘어 네트워크 쓰기 전에
  차단됐다. 새 SDK 출력으로 다시 진행했고 실행기 수신 시 관측 후 161ms였다.
  두 브라우저 요청은 모두 취소됐고 실제 HTTP 생성 요청은 한 번이었다.
  이 60초는 로컬 보호 규칙이며 네이버가 보장하는 토큰 유효기간이 아니다.
- `/RabbitWrite.naver`는 HTTP 200 JSON, `isSuccess: true`를 반환했다.
  반환된 글을 소유자 편집 API와 인증된 HTML 조회로 대조했고 제목·네 문단·
  순서·비공개 상태가 모두 일치했다. 이전 요청과 토큰 값도 달랐다.

이 결과는 **현재 세션에서 SDK 출력의 즉시 전달과 HTTP 쓰기**를 입증한다.
브라우저 없는 토큰 발급, 새 문서 구성, 서버의 만료·재사용 규칙 및 상업용
발행의 검수 통과까지 입증하지 않는다. 변환 알고리즘이나 환경 신호를
재구현하지 않았고 네이버 SDK가 준비한 값을 그대로 전달했다.

검증 실행기는 [private-create-probe-cli.mjs](../apps/naver-blog-api/tools/discovery/private-create-probe-cli.mjs)에
분리했다. 고정된 기술 검증 문구와 비공개·현재 발행만 허용하며, 현재 소유자를
조회한 뒤 영속 중복 방지 기록을 확보한다. 응답 유실·다른 글로의 리다이렉트·
문단 누락·공개 상태 변경 시 성공으로 표시하지 않는다. 정상 발행 CLI는
이 도구를 불러오지 않는다.

## API-only에 미치는 영향

네이버의 [2024 통합보고서, 91쪽](https://www.navercorp.com/api/article/download/7ff5d967-2b09-4ee4-be02-6069dd7c064e)은
nCaptcha를 이용자 브라우저에서 동작하는 invisible CAPTCHA로 설명한다.
현재 편집기에서 관측한 SDK/WASM 경로와 일치한다.
[공개 Open API 목록](https://developers.naver.com/products/intro/plan/plan.md)의
이미지 캡차 API는 별도 기능이며, 블로그용 nCaptcha 토큰의 대체 발급 경로로
확인된 것이 아니다. 이번 조사에서 지원되는 독립 발급 경로를 찾지 못했다는
결론이며, 모든 내부 계약이 존재하지 않는다는 뜻은 아니다.

- 정상 발행기의 `createPost`는 현재 `captured`, `client_exists`가 참이다.
  명시적인 헤드리스 SDK 입력을 받는 일반 비공개 신규 발행 경로를 추가했지만,
  실제 상업용 게이트 통과 발행은 아직 없으므로 해당 범위의 `live_replay`는
  거짓이다. 공유 입력 공급자와 문서 컴파일러의 고정 비공개 검증은 별도 기록한다.
- 별도의 `browserIssuedPrivateCreateProbe`는 `captured`, `client_exists`,
  `credential_propagated`, `live_replay`를 통과했다. `remnant_free`는 거짓이다.
  토큰과 문서 준비의 브라우저 의존성이 남으므로 완전한 API-only가 아니다.
- 정상 클라이언트는 신선한 헤드리스 입력이 없으면
  `CREATE_TOKEN_PROVIDER_UNVERIFIED`로 신규 발행을 차단한다. 공개 신규 발행은
  미검증 변형으로 차단하며, 기존 HTTP 수정·초안 수정·PNG 업로드는 유지한다.
- 별도의 `headlessPrivateCreateProbe`도 `captured`, `client_exists`,
  `credential_propagated`, `live_replay`를 통과했다. 창·확장은 사용하지 않아도
  Chromium 엔진이 남아 `remnant_free`는 거짓이다. 같은 초기 세션에서
  브라우저 재시작 후 재발급은 참이며 로그인 만료 후 자동 갱신은 미검증이다.
  후속 실행의 `Set-Cookie`는 `JSESSIONID`뿐이었으며, `NID_AUT`·`NID_SES`
  로그인 쿠키 연장은 관측되지 않았다.
- 독립 발급 경로가 확인되면 해당 실행 프로세스의 인증, 토큰의 사용 조건,
  새 문서 구성, 실제 쓰기 응답과 전체 재조회를 별도로 검증해야 한다.

기계 판독용 [검증 기록](../apps/naver-blog-api/references/ncaptcha-verification-2026-09-20.json)에
응답 키, 자산·영수증 해시와 미검증 항목을 남겼다. 쿠키, 토큰 값, 요청의
보안 검증 데이터 및 원시 인증 응답은 저장하지 않았다. 이 기술 테스트는
상업용 원고의 품질·근거·상품 최신성·모바일 검수 통과를 뜻하지 않는다.
