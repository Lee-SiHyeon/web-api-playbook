# 네이버 쇼핑커넥트 확장 준비

상품 검색 → 공정한 비교 → 판매 링크 → 네이버 블로그 게시 → 실적 확인 흐름에 쇼핑커넥트를 추가한다. 일반 네이버 쇼핑 검색 결과나 스마트스토어 URL을 제휴 링크로 간주하지 않는다.

## 현재 확인된 상태

2026-09-21 KST, 집 Windows `DESKTOP-TO2H6OD`에서 확인했다. 옆 세션의 계정 조회 구현 `79a0c25`를 별도 worktree와 `codex/naver-shopping-expansion` 브랜치로 가져왔다. 옆 세션은 마이리얼트립 업무 API를 계속 담당하며, 해당 작업 폴더와 브라우저 탭은 수정하지 않았다.

| 항목 | 실제 결과 |
| --- | --- |
| 로그인·계정 일치 | 독립 Node HTTP 조회 성공 |
| 크리에이터 플래그·계정 할당 | 있음 |
| 활성 스페이스·스페이스 목록 | 개설 후 독립 HTTP 조회에서 각각 1개 |
| 저장된 채널·경험 | 프로필 관리에서 블로그 연동 체크와 공동구매 진행 이력 `없음` 확인 |
| 준비 상태 검사 | `ready_for_scoped_discovery` |

| 상품 조회·판매 링크 | 상품 목록 표시와 메뉴 활성화 확인; 독립 HTTP 업무 API 미검증 |
| 카테고리 조회 | 브라우저 GET과 배열 응답 관측; 익명 HTTP는 403, 인증 HTTP 재현은 미실행 |

`creator=true`와 `accountAssigned=true`를 서비스 사용 준비 완료로 해석하면 안 된다. 최초 조회는 `blocked_space_setup`이었고, 사용자 요청으로 개설한 뒤 2026-09-20 17:10:55 UTC 독립 HTTP 조회에서 활성 스페이스 1개를 확인했다. 게이트는 `ready_for_scoped_discovery`로 바뀌었으나 상업 작업·게시 활성화는 여전히 false다. ## 완료된 개설과 활성화

사용자가 기존 블로그 채널 연동·스페이스 개설을 요청했고 공동구매 경험은 `진행 경험 없음`이라고 답했다. 해당 블로그, 기존 공개 프로필 이미지, 블로그명과 리빙 주제로 개인 크리에이터 스페이스를 개설했다. 저장 후 프로필 관리 화면에서 블로그 연동과 경험 `없음`을 다시 확인했다. 계좌·납세 식별정보는 입력하지 않았으며, 개설 화면은 개인 정산 정보를 수익 발생 뒤 등록할 수 있다고 안내했다. 활동 주제 변경에는 30일 제한 안내가 있다.

개설 POST는 브라우저 자동화로 제출했고 HTTP 200 및 생성 완료 안내를 확인했다. 이 쓰기 계약의 독립 HTTP 재현이나 범용 클라이언트 구현은 하지 않았다. 이후 계정 조회만 독립 HTTP로 재검증했다.

사용자가 별도 약관 동의를 확인한 뒤 `어필리에이트 통합 이용약관 동의서`의 필수 항목을 체크하고 제출했다. `PUT /brand-connect/command/creator-spaces/:spaceId/affiliate-terms/agree` HTTP 200, 후속 계정 GET의 `space.affiliateTermsAgreed=true`와 활동중 상태를 확인했다. 상품 찾기로 이동해 실제 상품 목록이 표시되고 발급 링크 관리·판매 실적 메뉴도 활성화됐다. 이 동의 작업과 확인은 브라우저 실행이며 독립 HTTP 약관 처리 API로 주장하지 않는다. [활성화 기록](../apps/affiliate-api-hub/references/naver-shopping-activated-2026-09-21.json), [권한 기준](https://help.naver.com/service/30027/contents/24101?lang=ko&osType=COMMONOS).

같은 사용자 요청으로 블로그에 공개 최상위 카테고리 `리빙·수납`, `주방·생활용품`, `가전·디지털`, `여행 준비물`, `여행·숙소`, `쇼핑 가이드`를 추가했다. 기존 `낙서장`과 글 7개는 유지했다. 저장 성공 응답, 관리 화면 새로고침 후 목록, 실제 블로그 카테고리 표시를 확인했다. 게시물 이동은 실행하지 않았다. 카테고리 쓰기는 브라우저 실행이며 별도 HTTP 클라이언트는 미구현이다.

## 구현 순서와 완료 조건

1. **계정·스페이스 준비 검사 — 구현·실검증 완료.** 기존 메모리 → stdin 전달로 이름이 지정된 계정 GET을 실행한다. 새 계정 응답에서 공간 필드를 확인하고 오래된 결과, 다른 계정, 브라우저만 성공한 결과를 거부한다. 활성 공간이 생겨도 결과는 `ready_for_scoped_discovery`까지만 올라간다. 링크 발급·게시 활성화가 아니다.
2. **상품 읽기.** 실제 쇼핑 메뉴가 열리면 그 공간의 카테고리, 상품 검색·상세, 필터·페이지 이동을 관측한다. 현재 관측된 카테고리 경로 외에는 API 경로를 만들지 않았다. 독립 HTTP에서 범위가 맞는 인증으로 재현한 뒤 클라이언트와 정규화를 구현한다.
3. **판매 링크 발급·조회.** 검토된 상품의 요청 형식을 관측하고 발급 링크 목록으로 소유 계정·상품·목적지를 재확인한다. 응답 유실 시 조회로 확인하고 재발급을 자동 반복하지 않는다. 공식 화면은 상품 찾기/상세에서 발급하고 발급 링크 관리 메뉴에서 조회하는 구조다. [발급 안내](https://help.naver.com/service/30027/contents/24104?osType=COMMONOS).
4. **콘텐츠 연결.** 공통 `ProductCandidate`, `Claim`, `LinkAttribution`, `PublishReceipt` 계약으로 전달한다. 가격·옵션·수량·판매자·배송비·멤버십·쿠폰을 분리하고, 비교 글은 비교 가능한 4개 이상 후보와 불리한 조건을 포함한다. 상품 상세 원문을 그대로 확신하는 설명이나 사용 후기처럼 쓰지 않는다.
5. **게시 게이트.** 실제 쇼핑커넥트 링크에 해당 제공자 고지를 붙인다. 기존 네이버 발행 게이트 브랜치의 최종 문서·중복 이미지·PC/모바일 화면·전체 본문 읽기 검증을 통합한 뒤 상업 게시를 연결한다. 가입 여부나 API 성공을 글 품질 승인으로 쓰지 않는다.
6. **실적·갱신.** 실제 리포트의 직접/간접 주문, 취소, 구매확정, 지급 금액을 구분한다. 클릭을 주문이나 확정 수익으로 승격하지 않는다. 제공자별 sub-ID 지원은 확인 전까지 미지원으로 취급하고 내부 post/product/placement 매핑을 유지한다. [실적 인정 기준](https://help.naver.com/service/30027/contents/24106?osType=COMMONOS).

## 정규화와 고지

상품 레코드는 최소한 제공자 상품 ID, 정확한 옵션/수량/판매자, 관측 가격 및 조건, 재고 상태, 수수료 규칙과 관측 시각, 출처를 가진다. 실제 API 스키마를 관측하기 전에는 상품 ID나 판매가 필드의 이름·의미를 추정하지 않는다. 목록 가격을 실제 결제 가격으로 바꾸거나 프로모션 수수료를 고정 수익으로 계산하지 않는다.

공식 안내 고지 예시는 “이 포스팅은 네이버 쇼핑 커넥트 활동의 일환으로, 판매 발생 시 수수료를 제공받습니다.”이다. 최종 게시물 첫 화면에서 보이는지 기존 게이트로 확인하며 혼합 제공자 글은 실제 사용한 제휴 관계를 모두 반영한다. [고지와 삽입 안내](https://help.naver.com/service/30027/contents/24104?osType=COMMONOS).

## 재개 방법

인증 전달은 `apps/affiliate-api-hub/tools/discovery/partner-session-handoff.mjs`의 기존 `runPartnerProbe`를 재사용한다. 쿠키는 현재 출처의 허용된 이름만 메모리에서 전달하고 원본 계정 응답·로그인 ID·스페이스 ID는 결과에 남기지 않는다. 초기 인증 취득은 브라우저 의존이고 계정 조회는 독립 HTTP다. 자동 로그인 갱신은 미검증이다.

`evaluateShoppingReadiness`는 비밀값이 없는 계정 조회 결과를 받는다. CLI도 같은 결과만 stdin으로 받으며, 준비가 안 됐으면 종료 코드 2를 반환한다. 5분 신선도는 로컬 검사 정책이며 네이버 세션 만료 시간의 추정이 아니다.

```text
node apps/affiliate-api-hub/scripts/partner-session-probe.mjs
node apps/affiliate-api-hub/scripts/naver-shopping-readiness.mjs
```

두 프로그램은 stdin 입력이 필요하다. 첫 번째에는 검토된 세션 전달 helper를 사용하고, 두 번째에는 첫 번째의 정제된 출력만 전달한다. 인증값을 명령 인수나 파일로 넘기지 않는다. 오래된 Git 검증 기록을 현재 준비 상태 입력으로 재사용하지 않는다.

새 테스트는 크리에이터 플래그만 있는 계정, 공간 미개설/대기/미관측, 활성 공간 이후에도 약관·업무 API 미검증 유지, 오래된 결과, 계정 불일치, 실제 stdin CLI의 중단 상태를 검사한다. 테스트 통과와 실제 사이트의 기능 전환 완료를 구분한다.
