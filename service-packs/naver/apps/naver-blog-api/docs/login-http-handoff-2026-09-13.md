# 로그인 → 독립 HTTP 연결 구현 — 실인증 미검증

## 이번 작업의 실제 결과

사용자의 후속 요청에 따라 기존 Windows 프로젝트를 직접 수정했다. 추가 비밀번호 입력, 쿠키 복사, 관리자 권한 변경을 사용자에게 요구하지 않았다.

`Home_Windows_Core`에서 소스 읽기와 패치는 실제 성공했다. 수정 전 `npm test`는 **26개 통과**, 실행 PC는 `DESKTOP-TO2H6OD`, Node는 `v24.10.0`이었다. 수정 후 `npm test`와 문법·diff 검사를 묶어 요청한 도구 호출은 실행 전에 다음 메시지로 차단됐다.

> 요청의 보안 상태를 결정하지 못해 이 도구 요청은 OpenAI에 의해 차단되었습니다.

이 결과는 테스트 실패나 네이버 거절이 아니다. 수정본 테스트·문법 검사의 실행 결과가 없다는 뜻이다. **새 테스트 22개를 추가했지만 실행하지 못했다. 기존 26개 통과 기록은 수정 전 코드에만 해당한다.** 도구 차단의 세부 원인은 응답에 제공되지 않았다. 다른 셸, 실행기 또는 전송 경로로 같은 차단 요청을 우회하지 않았다.

이전 headless worker 시작 차단은 그대로 미해결이며 이번에는 해당 실행을 재시도하지 않았다. 실제 로그인, 인증된 HTTP 요청, 새로운 XHR 수집, 게시·수정·삭제는 이번 작업에서 모두 0건이다.

## 수정한 연결

```text
HeadlessAuth의 정상 로그인 결과
  → SessionClient에 메모리 내부 전달
  → Node fetch로 보호된 관리자 루트 검사
  → 브라우저 종료 확인
  → 같은 프로세스에서 기존 통계 API / 관측된 읽기 문서 탐색
```

브라우저가 HTTP API 요청을 대신 실행하지 않는다. 다만 이 흐름은 소스 구현이며, 이번 작업에서 실제 계정으로 검증하지 못했다. 관리자 루트 검사는 계정 경로를 포함한 내비게이션과 로그인 HTML 여부를 대조하는 기존 HTML 기반 검사다. 별도의 계정 식별 JSON API를 관측·검증했다는 뜻은 아니다.

| 파일 | 변경 |
|---|---|
| `scripts/session-client.mjs` | 브라우저 없는 메모리 세션, 쿠키 대상·경로·만료 검사, 응답 Set-Cookie 반영, 기존 통계 클라이언트 연결 |
| `tools/discovery/headless-auth.mjs` | 검증 후 HTTP 세션 인계, 브라우저 종료 확인, 인계 실패 시 후보 세션 폐기 |
| `tools/discovery/api-workflow.mjs` | 로그인·인계·통계 읽기·문서 탐색·소스 후보 검토를 한 흐름으로 연결 |
| `tools/discovery/headless-worker.mjs` | 기존 로그인 전용 명령 처리를 통합 workflow에 연결 |
| `tests/session-client.test.mjs` | 합성 세션 테스트 11개 추가; 미실행 |
| `tests/api-workflow.test.mjs` | 합성 인계·탐색 테스트 11개 추가; 미실행 |

## 동작 계약

Worker의 `login`은 정상 로그인 결과가 `session_issued_unverified`일 때만 HTTP 인계를 시도한다. CAPTCHA, 추가 인증, 보호조치, 자격증명 거절이면 해당 상태를 반환하며 자동 재시도하지 않는다. `enableHTTP` / 기존 `verifyHTTP` 명령은 검증과 브라우저 종료까지 완료해야 `http_ready`를 반환하도록 변경했다.

`api`는 기존 관측 카탈로그의 통계 GET 55개만 사용한다. 쿼리는 기존 `resolveRequest` 검사를 그대로 적용한다. 인증·권한 오류, 로그인 HTML, 리다이렉트가 확인되면 후속 인증 요청을 중단한다. 만료된 세션을 무인으로 재로그인하거나 갱신하는 기능은 구현하지 않았다. Set-Cookie 수용은 기존 인증의 서버 응답 갱신 처리이지 독립적인 재로그인 기능이 아니다.

`inspect`는 관리자 루트·공개 블로그 루트와 응답에서 실제 관측된, 분류 가능한 읽기 문서 또는 공개 스크립트만 읽는다. 임의 URL이나 소스 문자열의 API 후보는 실행 대상으로 자동 승격하지 않는다. `scan`은 메모리에 있는 소스의 식별자와 경로 후보만 반환한다. `frontier` / `evidence`는 쿠키와 응답 원문을 반환하지 않는다. 공개 정적 스크립트에 로그인 쿠키를 전달하지 않는다.

단일 workflow는 읽기 작업 최대 100건, 문서 후보 2,000개, 메모리 원문 24 MiB, 소스 검사 100회로 제한한다. 통계 API의 기존 최대 1회 재시도는 별도이므로 작업 100건이 HTTP 전송 100회와 같지는 않다. 기존 전체 관리영역의 지속 frontier는 수정하지 않았고, 새 workflow의 탐색 상태는 현재 프로세스 메모리에만 유지한다. 전체 재귀탐색 또는 재시작 복구를 완료한 것으로 보고하지 않는다.

기존 글 게시·수정·삭제·이미지 업로드·스티커·서식 저장 계약은 여전히 미관측·미검증이다. 새 범용 쓰기 요청을 추가하지 않았다. HTML 문서 탐색을 XHR 캡처로 세지 않는다.
