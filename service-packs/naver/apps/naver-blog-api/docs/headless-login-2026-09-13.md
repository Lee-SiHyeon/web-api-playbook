# Headless 로그인 준비와 실제 실행 경계 — 2026-09-13

## 현재 결과

사용자는 자신의 네이버 계정으로 정상 로그인하고 XHR → API-only 개발을 이어가도록 요청했다. 기존 사용자 Chrome 연결 대신 한 개의 임시 headless context로 정상 로그인하는 도우미를 추가했다. **실제 로그인은 수행하지 못했다.**

Headless worker를 시작하는 `Home_Windows_Core.exec_command` 요청은 실행 전에 다음 메시지로 차단됐다.

> 요청의 보안 상태를 결정하지 못해 이 도구 요청은 OpenAI에 의해 차단되었습니다.

이 차단은 네이버 로그인 실패, CAPTCHA, 추가 인증 요구 또는 계정 잠금의 증거가 아니다. 이번 작업에서 로그인 페이지를 열거나 사용자 비밀번호를 입력·전송하지 않았다. 같은 실행을 다른 셸이나 전송 경로로 우회하지 않았다. 이후에는 외부 네트워크와 브라우저를 사용하지 않는 로컬 테스트만 실행했다.

## 저장한 코드

| 파일 | 역할 | 실제 검증 |
|---|---|---|
| `tools/discovery/headless-auth.mjs` | 정상 로그인 페이지의 관측된 입력 컨트롤 검사, 1회 로그인, 인증 단계 분류, 쿠키의 도메인·경로·만료 검사, 독립 HTTP 관리자 루트 검증 | 모의 테스트만 통과; 정상 로그인 및 HTTP 인증 검증은 미실행 |
| `tools/discovery/headless-worker.mjs` | 명령 처리, PTY 입력 에코 비활성화, 오류 원문 생략, 종료 시 세션 정리 | 파일 추가 및 정적 코드 확인; 실제 worker 시작은 도구 검사에서 차단 |
| `tests/headless-auth.test.mjs` | 브라우저 미실행, 자격증명 목적지 제한, 인증 실패 분류, challenge 중단, 중복 로그인 방지, 세션 정리 | 오프라인 8개 통과 |

Playwright에 맞는 Chrome Headless Shell 153.0.8010.12 (revision 1243), FFmpeg, Winldd 설치는 완료됐다. 설치 완료와 브라우저 실행·로그인 완료는 서로 다른 상태다.

사용자 비밀번호를 소스, 환경 파일, 증거 파일 또는 명령문에 기록하지 않았다. 테스트에는 합성 자격증명만 사용한다. 실제 비밀번호를 tool 실행 인자로 전달한 적도 없다. HAR, 저장된 브라우저 인증 상태, 쿠키 덤프, 로그인 화면 캡처도 생성하지 않았다.

## 검증 결과

오프라인 테스트 26개 모두 통과: 기존 18개와 신규 headless 인증 처리 테스트 8개. `git diff --check` 통과. 테스트는 브라우저 실행·네이버 접속 없이 모의 데이터로 수행됐다.

기존 통계 GET 55개 및 과거 실검증 22개 기록은 그대로다. 이번 작업의 실제 로그인, 현재 인증 세션 획득, 신규 XHR 수집, 인증된 HTTP 재현, 게시·수정·삭제·업로드는 모두 0건이다.

로그인까지 전부 순수 HTTP로 완성한 것이 아니다. 설계는 인증 확보에만 headless를 사용하고, 확인된 업무 API는 독립 HTTP 클라이언트로 실행하는 것이다. 아직 이 end-to-end 흐름을 검증하지 못했다.

이 문서는 실행 결과 기록이다. 미래 작업이나 지속 실행을 예약하지 않았으며, commit·push·실제 게시물 변경은 하지 않았다.
