**권장 수집·편집 흐름**

1. 뽐뿌·루리웹·11번가에서 새 항목과 변경 항목을 찾는다. 공지·광고·업체 글의 구분을 유지한다.
2. 커뮤니티 링크와 판매처 상품 ID를 연결한다. 같은 상품이 여러 게시판에 올라온 경우 하나로 묶되 출처별 반응은 따로 남긴다.
3. 판매처에서 동일 옵션의 가격·배송비·쿠폰 조건·종료 시각을 확인하고, 다나와 등에서 동일 조건의 비교가격을 확보한다.
4. 기존 `research/trend-radar`와 `community-radar`를 수요와 독자 질문의 보조 자료로 연결한다. 쇼핑 클릭 순위·자동완성을 절대 검색량으로 해석하지 않는다.
5. 할인 근거, 적용 방법, 구매에 맞는 사람, 주의할 옵션, 대안 상품을 포함한 글 초안을 만든다. 실제 사용하지 않았다면 사용 후기를 만들지 않는다.
6. 글에 사용할 정확한 판매 URL로 제휴 링크를 만들고 원래 목적지를 확인한다. 다른 판매처에서 발견한 최저가를 제휴 가능한 판매처의 가격처럼 쓰지 않는다.
7. 발행 직전에 가격·재고·날짜를 다시 확인한다. 종료되거나 바뀐 특가는 글에 상태를 반영한다.

스케줄을 구성한다면 사이트별 허용량·변경 속도에 맞추고, 중복 요청을 캐시로 줄이며 403·429에서 중단/백오프한다. 이 문서의 순서는 구현 제안이며 자동 실행 설정은 아니다.

**공개 OpenAPI와 내부 XHR의 구분**

네이버 공식 공지는 **쇼핑 검색 API를 2026-07-31 종료**했으며 NAVER API HUB 이관 및 대체 API 제공 대상에서도 제외했다고 명시한다. 오래된 쇼핑 검색 문서가 검색된다는 이유로 현재 작동하는 데이터원으로 선정하면 안 된다. 이 판단은 공식 종료 공지에 근거하며 인증키로 실제 호출해 본 결과는 아니다. [종료 공지](https://developers.naver.com/notice/article/32564), [이관 대상과 제외 항목](https://developers.naver.com/notice/article/32530)

검색어 트렌드와 Shopping Insight는 별도의 이관 대상이다. 이 둘까지 종료된 것으로 일반화하지 않는다. 서비스 내부 검색 XHR도 공개 OpenAPI와 별도로 조사해야 한다. 이번 후속 검증에서 내부 검색 JSON을 관측했고, 오늘끝딜 목록은 독립 HTTP까지 성공했다. 검색 XHR 재현 실패(418)와 특가 JSON 재현 성공을 별도 상태로 관리한다.
