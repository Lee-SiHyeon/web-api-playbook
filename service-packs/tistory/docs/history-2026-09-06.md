# 티스토리 XHR → API-only 탐색 결과

대상: https://i-never-stop-study.tistory.com/

## 확인한 범위

- 관리 링크를 너비 우선으로 탐색: 55개 경로. 콘텐츠, 카테고리, 공지, 서식, 댓글, 방명록, 휴지통, 방문 통계, 유입, 수익, 스킨, 사이드바, 메뉴, 모바일, 플러그인 분류, 링크, 팀블로그 포함.
- API 계약 79개: 실제 네트워크에서 관측한 JSON 응답 또는 쓰기 요청. 인증·공통 플랫폼 요청도 포함하므로 79개 전부가 블로그 관리 기능이라는 뜻은 아니다.
- 독립 Node.js 프로세스에서 조회 API 32개를 현재 세션으로 실호출. 응답 MIME·길이·SHA-256·스키마는 read-replays.json 참고.
- 게시 POST, 수정 PUT, 삭제 DELETE, 메뉴바 설정 PUT을 실제 실행했다. HTTP 재현 성공 및 관리 화면 재조회 확인.
- 테스트 글 212, 213, 214는 모두 삭제했다. 수정 조사 중 생성 경로를 잘못 사용해 214가 추가 생성됐으며 함께 정리했다.
- 메뉴바 위치는 원래 값(오른쪽 상단)으로 복원하고 새 조회로 확인했다.
- 스킨 다운로드: HTTP 200, 2,383,412 bytes, ZIP 시작 시그니처 확인. 압축 내부 파일 구조 검증은 미수행.

## 파일

- `discovery-map.json`: 부모 경로, 깊이, 시도, 상태, 화면의 조작 요소, 페이지별 요청.
- `api-catalog.json`: method/URL/필드 이름/스키마/출처 페이지. 관측과 HTTP 재현 상태를 구분한다.
- `cdp-events.jsonl`: CDP 이벤트 기반 누적 기록. 현재 세션에서 계속 수집 중이다.
- `read-replays.json`, `write-verification.json`: 독립 HTTP 및 쓰기 검증 증거.
- `client.mjs`: 통계 조회용 HTTP 클라이언트.
- `request.mjs`: 해당 블로그 `/manage/`에 한정된 명시적 HTTP 요청 실행기. 입력은 stdin JSON, 인증은 런타임 `TISTORY_COOKIE` 환경변수.
- `event-logger.mjs`: 발견 단계에 사용하는 재시작 가능한 CDP 로거. Node.js 24, 추가 npm 패키지 불필요.

## 실행

현재 사용자의 유효한 인증 쿠키를 실행 환경의 `TISTORY_COOKIE`로 공급한 상태에서:

```powershell
node client.mjs count
```

범용 실행기는 `{ "url": "관측된 절대 URL", "method": "GET" }` 형태를 stdin으로 받는다. 쓰기 요청에는 `body`를 함께 전달한다. HTTP 200/JSON은 전송 검증이며, 실제 업무 성공은 응답의 오류 필드와 독립 조회로 추가 판정해야 한다. 운영용으로 임의 요청을 자동 생성하지 않는다.

로거 재시작:

```powershell
node event-logger.mjs 'C:\Users\User\AppData\Local\Google\Chrome\User Data'
```

Chrome 원격 디버깅 연결 허용이 필요하다. 현재 로거와 중복 실행하면 로그가 중복될 수 있다. 현재 수집기는 실행 세션이 종료되면 멈추며 Windows 서비스나 예약 작업으로 등록한 상태가 아니다. 요청/응답 원문, 쿠키, 비밀번호, CSRF·토큰 값은 로그 파일에 남기지 않는다. 기존 `capture.mjs`는 별도 9224 브라우저용 초기 구현이며 현재 로깅은 event-logger 방식이다.

## 쓰기 계약

| 동작 | 관측한 요청 | 검증 |
|---|---|---|
| 게시 | POST `/manage/post.json` | 테스트 글 생성 후 조회·삭제 |
| 수정 | PUT `/manage/post/{id}.json` | 테스트 글 제목 수정 및 화면 확인 |
| 삭제 | DELETE `/manage/post/{id}.json` | 생성한 테스트 ID만 삭제, 목록에서 제거 확인 |
| 메뉴바 | PUT `/manage/design/setting.json` | `menubarType` 변경 후 `""`로 복원, 화면 확인 |

게시와 수정은 다른 URL·메서드다. `recaptchaValue`가 빈 관측 요청에서 재현됐으며, 향후 추가 인증이 요구될 경우 그 요구를 존중해야 한다. 일회용 인증값을 저장·재사용하지 않는다.

## 한계와 후속 탐색

메뉴 링크의 탐색 대기열은 처리했으나 이것이 모든 조합·모달·필터·쓰기 기능 검증을 의미하지 않는다. 작성자별 검색 중복 경로는 동일 계약으로 묶었다. 기존 콘텐츠 삭제, 플러그인 활성화/해제, 팀원 초대·권한 변경, 광고 계정 연동, 실제 스킨 교체 등은 실행하지 않았다. 지도에 보이는 controls는 관측 후보이며 작동 보장이 아니다. 쿼리 인자가 있는 목록·통계 API 중 다수는 네트워크 관측만 완료됐다.

카카오 로그아웃→재로그인은 브라우저에서 성공했다. 로그인 전체의 독립 HTTP 재현은 미완료다. 초기 폴링 캡처에서는 일부 응답 본문이 유실됐고 이후 CDP 이벤트 기반으로 교체했다. 현재 프로세스에 인증을 메모리로 전달하는 것은 검증했으나 영구 로그인 갱신·자격증명 저장 기능은 구현하지 않았다.

| 전환 상태 | 결과 |
|---|---|
| captured | 위 탐색 범위에서 확인, 모든 기능 전체는 아님 |
| client_exists | 통계 클라이언트 및 명시적 HTTP 실행기 존재 |
| remnant_free | 정상 HTTP 실행기는 브라우저 의존 없음; 최초 인증·발견은 브라우저 사용 |
| credential_propagated | 현재 사용자 세션을 별도 Node 프로세스에 전달해 검증; 영구 갱신 미구현 |
| live_replay | 조회 32개 및 위 쓰기 동작 검증; 로그인 전체와 나머지 계약 미검증 |
