# Installing a captured Gemini web contract

The runtime contract is a sanitized record of a real Gemini web request and its paired response. It is not a place to save browser bodies, prompts, response text, cookies, authorization headers, account identifiers, or session IDs.

The default manifest path is discovery/observed-contract.json. A missing file or a missing operation makes the corresponding client call return CONTRACT_NOT_CAPTURED.

The top-level record has version 1, service gemini-web, origin https://gemini.google.com, observedAt, auth, assetOrigins, and operations. The origin and each credential origin must match exactly. Media origins are separate and are added only when a browser response actually uses them.

Operations use explicit names such as identity, history_list, history_read, text, image, and video. Each must include observation.requestResponse=true, effect, request, and response. The request record contains the observed method, origin, path, ordered queryKeys, allowed headerNames, and contentType when a body is sent. A form request may also declare ordered bodyFieldNames. The response record contains the observed MIME type and one decoder name: json, batchexecute, text, or binary. Batchexecute entries also contain the exact RPC identifier from the paired response.

The auth record contains the single Gemini web origin, cookieNames, and headerNames. The installed identity and list contracts use the session cookies from the current browser request; observed analytics cookies (`_ga*` and `_gcl_au`) are excluded. Their values are supplied in a one-shot stdin bundle on Linux and never written to the repository. Operation-specific browser headers and the batch `at`, `f.sid`, and request ID remain in that in-memory bundle; the manifest stores names only. The validator rejects unobserved cookie names, request headers, and origins.

Mutating operations set effect to mutation and retryPolicy to never. Any request builder must be added as operation-specific code after the body shape and token sources have been observed. It must use the common transport and journal. The journal key is a hash of service, operation, authenticated actor, and a stable caller intent ID; a separate wire-body digest binds the exact one-shot dispatch. It stores no actor address, caller intent, prompt, session token, or response body.

The XSSI parser uses the frame length unit and measured JSON-length overhead recorded in each batchexecute operation. Gemini captures use UTF-16-code-unit lengths; the decoder finds the raw JSON value boundary and checks that its code-unit length plus `frameLengthOverheadUnits` matches the declared frame length. It then skips only the observed CR/LF separators, preserving a digit that begins the next length header. Legacy byte lengths require an explicit operation contract. The transport retains bounded raw response chunks and decodes the complete UTF-8 body once, so a multibyte character split across socket chunks remains intact. The installed `history_list` contract pairs the browser-captured `MaZiqc` request and response and has an operation-specific request builder and RPC decoder. The direct client verifies the expected owner from the authenticated `/app` document before running that read. Other capabilities remain incomplete until their own request/response captures, operation builders, and direct replays are added.
