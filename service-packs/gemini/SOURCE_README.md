# Gemini web direct HTTP client

This repository has live direct-HTTP evidence for owner identity, conversation list/search/detail reads, model catalog, text generation, image generation and retrieval, and video generation and retrieval. Final feature acceptance requires canonical receipts whose feature-scoped auth, operation contract, and handler closure still match. The text proof used a fresh one-shot intent: the browser request was aborted before network submission, its captured body was replayed once over HTTPS, and the direct response was decoded and read back through the observed `hNvQHb` detail call. The browser text contract remains request-only; the successful direct response does not turn it into a browser-paired response contract.

The text response contained eight ordered UTF-16-length frames and four main-candidate chunks. The detail read matched the requested task, assistant marker, raw API conversation ID echo, and visible route binding. The mutation journal is reconciled with one dispatch and no retry. The response-ID comparator was unavailable, so the evidence does not claim that comparison. The safe receipt is [gemini-protocol-decoder-verification-2026-10-06.json](verification/one-shot/gemini-protocol-decoder-verification-2026-10-06.json); it stores hashes and booleans, not the prompt, answer, request or response bodies, cookies, tokens, or conversation IDs.

The video writer and download have separate evidence. An independent generation request returned HTTP 200; the exact task was subsequently matched by prompt hash, API conversation ID echo, and route binding. Its observed asset URL then returned HTTP 200 `video/mp4`, and MIME, format signature, independent file readback, and the browser artifact hash matched. See [media-api-readback-2026-10-06.json](discovery/media-api-readback-2026-10-06.json) and [media-download-direct-2026-10-06.json](discovery/media-download-direct-2026-10-06.json). Downloading the artifact did not issue another generation request.

The image run has an exact task-bound detail readback and an independently downloaded PNG. The verified image is 512 by 279 pixels; full-resolution retrieval remains unverified. Its normal download chain uses the source-observed Google redirect hosts and ordinary cookies only on the exact authenticated intermediate hop. See [media-browser-capture-2026-10-06.json](discovery/media-browser-capture-2026-10-06.json).

The 16-group scope in [feature-checklist.json](discovery/feature-checklist.json) remains intact. Live facts are recorded in safe receipts; the offline checker distinguishes missing canonical evidence from historical runs whose current source binding needs re-verification. New scoped receipts bind the global auth section, the feature's required operation contracts, and named handler functions. This excludes offline checker changes and unrelated CLI branches. Older receipts without a captured scope retain their original full hashes and are never backfilled. History acceptance requires independent list, search, and exact-task detail cases. Earlier text and media intents that remain held or unresolved are not retried or relabeled.

The Node 24 client uses an origin-locked HTTPS transport, one-shot stdin session handoff on Linux, bounded response parsing, a no-replay mutation journal, and image/video MIME and signature checks. `hNvQHb` uses the captured eight-argument template with the raw API conversation ID in memory; its route ID is checked separately. The text parser preserves progressive null-selector frame order and stable conversation/request identifiers without pretending the browser captured a response pair.

## Authentication and evidence

Owner verification uses the current app bootstrap's active principal field `WIZ_global_data.oPEP7c` and the app orchestrator. An email appearing only in saved-account or chooser markup cannot authenticate that account. An anonymous control must also lack the expected active principal. Failed owner checks clear the cached owner; identity response buffers are cleared after their digest and positive/negative checks are complete.

The current native Chrome profile exposed the expected provider-authenticated session; the client received it through stdin and refreshed the direct HTTP context. Fresh authenticated and anonymous `/app` reads verified the same owner, while the profile, cookies, and account settings remained unchanged. The canonical [login receipt](verification/features/login.json) and [current handoff receipt](verification/one-shot/gemini-owner-handoff-current-2026-10-06.json) record a session handoff, not a new login timestamp. No password was sent to a provider API and no challenge bypass was used. Session values stay in memory and are not stored in receipts.

Required cookies may include their observed `expires` value in epoch seconds; `-1` represents a browser session cookie. Known expired cookies fail with `SESSION_EXPIRED` before HTTP transmission. `renewSession({expectedOwner, acquireSession})` verifies a normally acquired replacement using independent authenticated and anonymous `/app` reads before an atomic same-owner handoff. Failed candidates, concurrent handoffs, or a session changed during verification cannot overwrite the active session. It never retries an earlier mutation. A live CLI run recovered deliberately expired **local metadata** using the current normal profile session: owner HTTP 200, unchanged credential values, and stable source hashes. The native profile and provider cookies were not changed. See [the scoped handoff receipt](verification/gemini-session-client-handoff-live-2026-10-06.json). Provider cookie rotation, recovery of a server-expired login, and an HTTP password-login endpoint remain unverified.

`node scripts/check-features.mjs` audits only the installed checklist, observed contract, and exact canonical receipt paths. It makes no network requests and starts no browser or provider. `stored_receipt_consistent` means a receipt matches its installed feature scope and handler hashes; it does not mean the checker just contacted Gemini. Use `--json` for machine-readable output and `--strict` to return exit code 2 while required or unresolved-conditional features remain incomplete.

Adapter bindings cover identity, history list/search/detail, models, minimal supported preference reads, the source-verified preference update, public-link reads, and text/image/video dispatch. Text evidence keeps `requestResponsePaired: false` and uses a separate direct-replay record to require the captured request abort, one direct dispatch, response decoding, and same-task detail readback. Missing installed evidence is reported as `live_evidence_missing`; source drift is reported as `needs_reverification`.

The current first-party `LQaXg` bundle maps `ESY5D` to preference reads and `L5adhe` to `UpdateUserPreferences`. Selector 41 is `side_nav_open_by_default`; its current value is read with the minimal `[null,[41]]` request. The source setter is a typed boolean `By` field at zero-based dense-array slot 40, with selector `[41]`. A corrected direct HTTP update changed the preference from `true` to `false`, the immediate independent `ESY5D` read returned `false` with its own response byte count and digest, and a second direct update restored `true` with readback. The source and owner hashes were stable across the run. An earlier off-by-one request returned HTTP 200 but left the value unchanged; its receipt is preserved. Browser startup update requests were aborted before network submission. The settings writer does not allow activity, memory, personal-context, security, or account settings. See the [source contract](discovery/gemini-settings-update-contract-fragment-2026-10-06.json), [canonical settings receipt](verification/features/settings.json), [current response-complete live receipt](verification/one-shot/gemini-settings-update-live-v2-2026-10-06.json), [earlier live receipt](verification/one-shot/gemini-settings-update-live-2026-10-06.json), and [offset correction receipt](verification/one-shot/gemini-settings-update-offset-correction-2026-10-06.json). Shared Chrome CDP helpers stop their Playwright driver without closing the shared browser or context.

## Commands

- `npm test` runs offline contract, parser, security-boundary, journal, transport, feature-audit, and media checks.
- `npm run lint` checks JavaScript syntax.
- `npm run gemini -- status` reports safe contract and session-provider readiness booleans.
- `npm run gemini -- evidence` reports per-capability evidence states.
- `npm run gemini -- identity --session-stdin --expect-owner account@example.com` verifies the protected `/app` principal over direct HTTPS with an anonymous control.
- `npm run gemini -- session-renew --envelope-stdin --expect-owner account@example.com` accepts `session` and `replacementSession` through stdin, verifies the same owner, and installs the replacement in memory. The replacement must come from a normal acquisition flow; this command does not mint credentials or automate provider login.
- `npm run gemini -- history list --session-stdin --expect-owner account@example.com` reads the conversation list; `npm run gemini -- history read --envelope-stdin --expect-owner account@example.com` reads one task-bound detail.
- `npm run gemini -- settings-read-one --envelope-stdin --expect-owner account@example.com` reads only the source-mapped sidebar-default boolean.
- `npm run gemini -- settings-update --envelope-stdin --expect-owner account@example.com --caller-intent stable-intent --confirm` performs one confirmed source-verified settings update after a direct baseline check; the stdin envelope supplies `preferenceKey`, `value`, and `baselineValue`.
- `npm run gemini -- settings-update-test --envelope-stdin --expect-owner account@example.com --caller-intent stable-intent --confirm` performs one bounded inverse-value test and restores the exact direct-read baseline. An optional boolean `baselineValue` in the stdin envelope makes the test stop before dispatch if the direct baseline differs.
- `node scripts/verify-history.mjs` accepts a JSON packet on stdin with `session`, `expectedOwner`, `query`, and `expectedIntent`. It refreshes the direct HTTP context and verifies a matching conversation across list, search, and detail. An optional `expectedConversationSha256` disambiguates an existing task without placing its ID in command arguments. Only after positive owner/task checks and unchanged auth/operation source scopes does it write canonical history receipts. Input credentials, queries, IDs, and response values are never written to the receipts. This verifier starts no browser and performs no mutations.
- `npm run gemini -- text --envelope-stdin --expect-owner account@example.com --caller-intent stable-intent --confirm` permits one caller-authorized mutation through the no-replay journal. The browser capture helper is discovery only and aborts the matching browser send before that direct request.
- `npm run gemini -- public-status` reads anonymous app-shell metadata only. The optional `--transport chrome` path uses `curl_cffi` and is not an authenticated browser session.
- `npm run credential-selftest` performs a guarded DPAPI write/read/delete check under a random app-scoped filename on supported Windows environments.

The public app-shell read and [published source candidates](discovery/public-source-contracts-2026-10-03.json) remain separate from authenticated private-operation evidence. See [observed-contract-schema.md](docs/observed-contract-schema.md) for the sanitized manifest interface.
