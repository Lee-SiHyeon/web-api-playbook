## x-client-lct 제거 대조

브라우저의 정상 앱 흐름이 만드는 요청에서 특정 필드만 제외했습니다. 사이트가 생성한 값을 새로 만들거나 조작하지 않았으며 값·쿠키·원문 응답을 출력하거나 파일에 보관하지 않았습니다. 테스트가 만든 페이지에서 XHR/fetch의 헤더 설정만 바꿨고 브라우저 UA·navigator·전송 지문은 변경하지 않았습니다.

## 독립 HTTP 재현의 한계

SDK 컨텍스트의 네이티브 재현은 작업이 만든 익명 컨텍스트에서 정상 사이트 흐름으로 발급된 최신 요청을 사용했습니다. 정상 브라우저200의 일반 헤더 프로필과, 브라우저가 아직 보내지 않은 새 SDK 요청의 컨텍스트를 메모리에서 결합했습니다. 토큰값은 프로세스 인자·파일·로그에 넣지 않고 표준 입력으로만 전달했습니다.

브라우저 요청은 재현 전후 모두200·상품 번호 일치였지만 Node24 fetch와 표준 HTTP/2는 lct만 전달한 경우와 세 필드를 모두 전달한 경우 모두429였습니다. 아직 분리하지 못한 전송·세션 결합과 보호 정책이 남아 있으므로 TLS 지문, IP 평판, 헤더 순서 등 하나를 원인으로 확정하지 않습니다.

일반 헤더를 그대로 재작성한 네트워크 인터셉트 실험은 정상 대조부터429가 됐습니다. 그 실험으로 헤더 필수 여부를 판단하지 않았습니다. 후속 페이지 헤더 제거 방식에서는 정상 대조200이 유지됐고 lct 제거204/복원200을 재현했습니다. 첫 SDK 재현도 일반 헤더 일부 누락과 앞선 브라우저429로 비교 조건이 맞지 않아 제외하고, 이후 전체 헤더와 전후200을 확보한 결과를 채택했습니다.

## 현재 결론

상품 문서 요청에서의429와, 정상 브라우저 상품 JSON에서 lct를 생략할 때의204를 각각 확인했습니다. 요청 형식 보완만으로 독립 HTTP가 정상화됐다는 근거는 없습니다. 브랜드 상품 API-only 런타임은 여전히 미완료 상태입니다.
