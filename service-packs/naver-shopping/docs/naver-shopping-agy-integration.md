# AGY 가격 조회 작업 통합

2026-09-30 옆 AGY의 작업 기록에서 네이버 쇼핑 관련 파일을 확인하고 최신 원본 세 개를 읽기 전용 스냅샷으로 보존했습니다. 통합 기능은 기존 Node.js HTTP 클라이언트·CLI에 연결했습니다. 원본 Python 파일은 수정하지 않았습니다.

원본과 해시는 [기여 내역](../references/naver-shopping-agy-contributions.json)에 기록되어 있습니다.

- `naver_price_engine.py`: 통합검색 상품 카드 파싱, 가격 통계, 정렬, 포함/제외 정규식·가격 범위 필터.
- `price_compare.py`: 키워드 가격 조회와 필터 CLI.
- `test_price_engine.py`: 파싱·통계·필터의 합성 fixture 테스트 3개. 원본 스냅샷에서도 통과했습니다.

418이 반환되던 로컬 `client.py`, `parser.py`, `cli.py`, `test_client.py`와 관련 bytecode는 삭제했습니다. 해당 전용 검색 경로도 제공 카탈로그에서 제거했습니다. 기존 공개 피드, 브랜드 상품/전체 리뷰 계약과 실패 처리 코드는 공통 클라이언트를 사용합니다.

## 추가 사용법

```bash
npm run naver:shopping -- integrated-search --query 노트북 --limit 20
npm run naver:shopping -- integrated-search --query 맥북프로 --exclude '케이스|필름|커버|중고' --min-price 1000000
npm run naver:shopping -- integrated-search --query '아이폰 16' --regex '자급제.*(128|256)GB' --max-price 1500000
```

이 명령은 `search.naver.com/search.naver?where=nexearch&query=...`의 **통합검색 쇼핑 카드**를 독립 HTTP로 읽습니다. 상품 제목·표시 가격·할인 전 가격·조건부 쿠폰 가격·확인되는 판매처 수·평점·리뷰 수를 제공합니다. 일반 쇼핑 검색의 전체 상품 목록이나 리뷰 본문이 아닙니다.

필터는 가져와서 검사한 카드에만 로컬로 적용됩니다. `inspectedCount`, `matchedCount`, `filtering`에 그 범위를 표시합니다. 제한은 최대 40개 카드이고, 페이징은 미확인입니다. 필터 결과 0개는 정상 결과이며 가격 통계는 null입니다. HTTP 실패, 쇼핑 블록 미노출, 스키마 변경은 오류로 반환합니다.

정규식은 최대 160자, 문자/문자 클래스/앵커, 그룹 최대 4개(깊이 2), 대안 최대 8개, 와일드카드 `.*` 한 개를 지원합니다. 역참조·lookaround·그 외 반복은 입력 단계에서 거부합니다. 일반 정규식 전체를 지원한다고 표시하지 않습니다.

## 원형에서 수정한 부분

같은 HTTP 문서를 원형과 새 파서에 입력하여 가격 차이를 재현했습니다. HTML 원문은 보관하지 않고 길이·해시와 정규화된 비교 값만 남겼습니다.

- 베이직북14 원형 반환: 959,000원. 문서에서 이 값은 **할인 전 판매가**입니다.
- 수정된 현재 표시 가격: 598,000원. 조건부 쿠폰 표시 가격 597,000원은 별도 필드입니다.
- 베이직북16 원형 반환: 1,440,000원. 수정된 현재 표시 가격: 798,000원, 조건부 쿠폰 가격: 797,000원.
- 해당 시점 삼성 제품의 최저 표시 가격 1,257,970원은 원형과 새 파서가 일치했습니다.

가격은 관측 시점의 값이며 이후 달라질 수 있습니다. 현재 가격 행, 할인 전 가격 행, 쿠폰 가격 행을 각각 읽어 첫 금액이나 조건 미확인 쿠폰 가격을 현재 결제 가격으로 사용하지 않습니다. 형제 상품의 금액을 가져오지 않도록 카드의 상품 ID 범위도 검사합니다.

원형의 통신 실패 → 빈 목록/0원 통계 처리는 오류로 바꿨습니다. 없는 판매처를 1개로, 없는 평점/리뷰 수를 0으로, 제목을 검색어로 만들어 넣지 않습니다. `1.4만`은 정확한 14,000건으로 단정하지 않고 표시 문자열과 근사값/정밀도를 구분합니다.

원형의 가격순 재배열 후 순위 덮어쓰기는 `sourceOrder`와 `priceOrder`로 구분했습니다. `sourceOrder`는 파싱한 문서의 순서이고 검색 순위나 인기 순위가 아닙니다. 광고 여부도 미확인으로 남깁니다. 같은 상품 ID에서 다른 표시 가격이 발견되면 서로 다른 관측으로 보존합니다.

`observedPriceRangeKrw`는 반환된 표시 가격의 최저·최고·산술평균입니다. 시장 전체 최저가나 동일 옵션 간 우열을 뜻하지 않습니다. 옵션·수량·멤버십·쿠폰·배송의 동등성과 결제 가격은 별도 검증이 필요하며 `comparisonReady`는 false입니다. 추적용 bridge 링크를 검증된 상품 URL로 바꿔 만들어 반환하지 않습니다.

## 검증 경계

Node.js 기본 fetch로 통합검색 카드 조회의 HTTP 200을 확인했습니다. 새 원형 회귀 테스트는 할인 전/현재/쿠폰 가격 구분, 카드 혼합, 줄임 리뷰 수, 가격 통계, 필터, 입력 경계, 실패의 빈 결과 처리 방지를 포함합니다.

실제 `노트북` 결과는 3개 카드를 검사했고, 액세서리/중고 제외 및 최소 600,000원 조건을 적용한 뒤 2개가 남았습니다. `맥북프로` 결과도 별도로 5개 카드를 조회했습니다. 서로 다른 모델·옵션·액세서리가 포함될 수 있으므로 조회 성공이 비교 가능성이나 추천 적합성을 증명하지 않습니다.

브랜드 상품/전체 리뷰의 독립 HTTP 429는 별도 제한으로 남습니다. 현재 DOM 가격 클래스는 실제 관찰한 계약이며 변경되면 `SCHEMA_CHANGED`로 실패합니다. 향후 차단 없이 계속 수집된다는 보장은 없습니다.
