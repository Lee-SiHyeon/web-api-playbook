# 브랜드 스토어 429 재현 조사 (2026-09-30)

## 확인 결과

기존 브라우저 캡처에서 상품 JSON GET과 전체 리뷰 POST가 HTTP 200 및 예상 JSON 스키마로 관측된 경로를 확보했습니다. 현재 워커에서 같은 상품·스토어·원상품·판매자 연결과 요청 형식을 사용하여 재현했습니다.

| 검사 | 현재 워커 결과 |
|---|---|
| 스토어 첫 문서 GET | 429 HTML |
| 상품 문서 GET | 429 HTML |
| 정확한 상품 JSON GET, 현재 클라이언트 기본 헤더 | 429 HTML |
| 같은 JSON GET, 캡처의 공개 메타 헤더 4개 | 429 HTML |
| 정확한 원상품/판매자 연결의 리뷰 POST | 429 HTML |
| 새 익명 Chromium의 스토어 첫 페이지 | 429 HTML |
| 새 Chromium의 쇼핑 행사장 경유 | 행사장 307 → 로그인 페이지 200, 정상 쇼핑 진입 미완료 |
| 위 익명 쿠키 발급 후 스토어 첫 페이지 | 429 HTML |
| 양성 대조: shopping.naver.com/promotion GET | 200, 정상 __NEXT_DATA__ 포함 |

제한 응답은 모두 23,585바이트이며 동일한 SHA-256을 갖고, 일시적인 접근 제한 안내를 포함합니다. `Retry-After`는 없었습니다. 정상 대조 응답도 서버 헤더가 `nfront`이므로 서버 이름만으로 WAF를 확정한 것은 아닙니다. HTML 본문 내용과 경로 간 동일 응답, 첫 브라우저 페이지 결과를 함께 근거로 사용했습니다.

## 단정할 수 있는 것과 미확인 사항

- 상품 경로와 `withWindow=false`, 전체 리뷰 POST의 필드/값 연결은 기존 성공 캡처와 일치합니다. 삭제한 search.shopping.naver.com 경로를 재사용하지 않았습니다.
- API 요청 전에 스토어 첫 문서부터 제한되므로, 잘못된 상품 번호나 리뷰 body만으로 현재 현상을 설명할 수 없습니다.
- 공개 헤더 `x-service-type`, `Accept`, `x-client-version`, `Content-Type`를 맞추는 것만으로 해결되지 않았습니다.
- 실제 브라우저 캡처에는 `x-client-rts`, `x-client-lct`, `x-client-rtk` 등의 추가 헤더도 있습니다. 현재 클라이언트는 이 컨텍스트를 재현하지 않습니다. 해당 값의 의미·필수 여부·정상 발급 흐름은 미확인이므로 완전한 요청 재현이나 코드 무결함을 주장하지 않습니다. 값 복사·서명 생성·추측은 수행하지 않았습니다.
- 새 익명 Chromium도 첫 페이지에서 동일하게 제한됐으며 정상 상품 API를 발행하는 단계까지 도달하지 못했습니다. 현재 워커의 접속 환경과 세션/클라이언트 컨텍스트 문제를 분리해 확정할 수 없고, IP만의 원인이라고 단정하지 않습니다. 다른 기기·네트워크나 기존 인증 세션의 독립 HTTP 성공은 미검증입니다.
- 행사장 경유 흐름도 확인했으나 브라우저는 로그인 페이지로 이동했습니다. 해당 200은 정상 쇼핑 진입이나 상품 API 성공으로 취급하지 않습니다. 신규 익명 쿠키가 발급된 후에도 스토어 문서는 같은 429였습니다. 로그인·캡차 풀이·기존 프로필 접근·헤더 값 생성은 수행하지 않았습니다. 로그인 HTML의 캡차 관련 문자열은 실제 활성 챌린지라고 확정하지 않습니다.
- 이번 범위에서는 현재 워커에서 성공하는 익명 상품 상세 JSON/전체 리뷰 경로를 찾지 못했습니다.

## 코드 수정

429 HTML이 공통 접근 제한 문구를 포함해도 HTTP 상태를 먼저 판단해 `RATE_LIMITED`로 분류하도록 수정했습니다. 응답의 `Retry-After`를 receipt에 남기며 자동 재시도는 추가하지 않았습니다. 제한 HTML 우선순위와 대기 헤더 처리에 대한 회귀 검사 4개가 통과했습니다. 이 검사는 오류 분류를 검증하며 실제 상품/리뷰 조회 성공의 증거는 아닙니다.

## 공식 쇼핑 검색 API와 구분

개발자센터의 쇼핑 검색 Open API는 2026-07-31 종료됐고 NAVER API HUB 대체도 제공되지 않는다는 [네이버 공식 공지](https://developers.naver.com/notice/article/32530)를 확인했습니다. 남아 있는 옛 쇼핑 검색 API 레퍼런스 페이지를 현재 가용 API로 취급하지 않습니다. 판매자 커머스 API는 [조회 대상 판매자의 인증 토큰이 필요한 별도 경계](https://apicenter.commerce.naver.com/docs/commerce-api/current/%ED%8C%90%EB%A7%A4%EC%9E%90)이며, 익명 타 스토어 크롤러의 대체로 구현하거나 검증한 상태가 아닙니다.

## 사용자 브라우저 관측과 비교

사용자는 정상적으로 열린 상품 화면에서 할인 전 72,000원, 표시 가격 64,800원, 리뷰 집계 9,910건 및 평점 4.79를 확인해 제공했습니다. 이는 사용자 제공 화면 정보이며 이 워커의 상품 JSON 또는 전체 리뷰 본문 API 성공으로 표시하지 않습니다. 사이트 데이터가 모든 환경에서 사라진 문제는 아니라는 비교 근거입니다. 동일 기기의 네트워크·브라우저·독립 HTTP 비교와 인증 상태는 아직 미확인입니다.

## 후속 가설 대조

이전에 사용한 정상 브라우저의 200을 재현하고, 새 익명 컨텍스트·쿠키 포함/생략·동적 헤더 없는 브라우저 fetch·Node HTTP/2·표준 curl을 대조했습니다. 결과는 [후속 검증](naver-store-hypothesis-results.md)에 정리했습니다. 동적 헤더와 로그인 필요 가설은 해당 정상 브라우저 조건에서 반례를 얻었으나 독립 HTTP 성공은 여전히 확인되지 않았습니다.
