# 이전 200·현재 429 가설 검증

이 문서는 초기04:55 UTC 조건의 기록입니다. [09:20~09:43 UTC 후속 대조](naver-store-new-hypotheses.md)에서는 현재 헤라 상품의 정상 요청에서 x-client-lct 제거204·복원200을 확인했습니다. 초기의 동적 헤더 생략 성공을 현재 요구 조건으로 일반화하지 않습니다.

2026-09-30 현재, 이전에 쓰던 정상 브라우저와 독립 HTTP를 대조했습니다. 대상은 헤라 브랜드 스토어의 상품 JSON 및 전체 리뷰 읽기이며, 성공 중인 통합검색·공개 피드·오늘끝딜·여행 HTTP와 혼동하지 않습니다.

## 이전에 왜 됐는가

이 세션의 원래 캡처 명령을 확인했습니다. 2026-09-29 22:39~22:46 UTC 성공 캡처는 기존 브라우저에 CDP로 연결하고 `browser.contexts[0].new_page()`를 사용했습니다. 새 브라우저나 새 컨텍스트를 만든 것은 아니었고, Node 독립 HTTP 호출 성공도 아니었습니다. 그 기존 브라우저가 현재도 연결 가능해 같은 상품 문서·상품 JSON 200을 재현했습니다.

| 대조 실험 | 결과 | 입증 범위 |
|---|---|---|
| 기존 정상 브라우저: 상품 문서·JSON | 200 | 이전 성공의 실행 주체 재현 |
| 같은 브라우저의 새 익명 컨텍스트 | 문서 200, 쿠키 포함 JSON 200 | 로그인 및 오래된 저장 상태가 필수는 아님 |
| 브라우저 JSON, 일반 공개 헤더 + 쿠키, x-client 동적 헤더 없음 | 200 | 해당 환경에서 rts/lct/rtk는 필수 아님 |
| 같은 브라우저 JSON, 쿠키도 생략 | 429 | 해당 상품 API의 익명 컨텍스트 조건 차이 관측 |
| 브라우저 리뷰 POST, 쿠키·동적 헤더 모두 생략 | 200, 페이지1의 리뷰20개 | 해당 리뷰 경로 정상 응답 관측 |
| 같은 시각 Node 익명 JSON | 429 | 시간 경과만으로 모든 요청이 해결되지는 않음 |
| Node 정상 익명 쿠키·메타·Origin/Referer·발급자 UA 재현 | 429 | 쿠키 전달만으로 Node가 정상화되지는 않음 |
| Node 표준 HTTP/2, 실제 정상 요청의 서명 없는 공개 헤더·쿠키 | 429 | HTTP/2 선택만으로 해결되지 않음 |
| 시스템 기본 curl 표준 HTTP/2, 실제 요청 컨텍스트 | 상품·리뷰 모두429 | 다른 일반 HTTP 클라이언트도 현재 실패 |

브라우저에서 직접 수행한 fetch를 독립 HTTP 클라이언트 성공으로 표시하지 않습니다. 브라우저 200을 API-only 런타임 완료로 승격하지 않습니다. 쿠키 및 서명값은 파일·로그·표준 출력에 저장하지 않았고, 서명·토큰 생성이나 브라우저 지문 변경을 수행하지 않았습니다.

## 현재 판단

- 상품 URI/리뷰 body 오입력만의 문제라는 설명은 해당 관측 경로에서 배제됩니다.
- x-client-rts/lct/rtk 누락이나 로그인 필요만으로 실패를 설명할 수 없습니다. 실제 해당 헤더 없이 브라우저에서 정상 응답했고 새 익명 컨텍스트도 정상화됐습니다.
- Node24와 브라우저의 공개 출발 주소는 동일한 공개 trace 엔드포인트에서 같았습니다. 실제 주소는 출력·저장하지 않았습니다. 이 비교는 특정 trace 대상에 한정되며 네이버에 대한 사이트별 경로 차이를 확정적으로 배제하지 않습니다.
- 브라우저 전송 환경과 일반 HTTP 전송 환경 간 결과 차이는 확인됐습니다. TLS/HTTP2 세부 특성, 사이트별 경로 및 보호 정책 중 정확한 원인은 아직 분리되지 않았습니다. 새 headless 브라우저도 실패했다는 이유로 Node 전송 특성 전체를 기각하지 않습니다.
- Retry-After는 선택적 헤더이므로 없다는 사실만으로 rate limit을 배제하지 않습니다.
- 현재 일반 독립 HTTP로 동작하는 브랜드 상품 상세·전체 리뷰 클라이언트는 확인되지 않았습니다. 기존 API-only 실행 경로의 partial 상태를 유지합니다.
